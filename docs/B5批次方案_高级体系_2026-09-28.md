# B5 批次方案：高级体系（2026-09-28）

> 目标：消化 M-9 / M-13 / M-14 / M-15 / M-18 五项"高级体系"。核心原则不变：数据与语义对齐 ST，
> 能走 ST 现成端点的走端点，能在 App 本地做的纯本地做。

## ST 事实（源码实测）

- **QR 互通**：settings 响应带 `quickReplyPresets`（QuickReplies/*.json 全量解析，settings.js:261）；
  写回 `POST /api/quick-replies/save {name, ...set}`（整文件原样落盘，quick-replies.js:10）。
  QR set 文件形状：`{id?, name, qrList: [{id?, label, message, title?...}]}`，ST 端解析同名键
- **STscript**：命令分散在 slash-commands.js / variables 扩展；语法：`/command arg | /cmd2 {{pipe}}`，
  `{{pipe}}` 接收上一命令输出，`{{var}}`/`{{getvar::x}}` 读变量。QR 消息以 `/` 开头即按脚本执行
- **Instruct**（instruct-mode.js:387-457）：`formatInstructModeChat` —— prefix 按角色取
  input/system/output_sequence（首/末变体优先），suffix 同理；`names_behavior: none|force|always`；
  `{{name}}` 宏替换；wrap=true 时片段间以 '\n' 连接且空 suffix 补 '\n'。字段全量在
  `settings.power_user.instruct`
- **NovelAI**：`POST /api/novelai/generate {input, model, parameters:{...}}`（novelai.js:167），
  服务端读 Novel 密钥；无密钥 400
- **角色重命名**：`POST /api/characters/rename {avatar_url, new_name}`（characters.js:1053），
  服务端连聊天目录一起迁移；App 侧重命名后需刷新角色与会话列表
- **data-maid**（data-maid.js）：`/report` 生成清单 + token → `/finalize {token}` 执行清理，
  属"报告确认"型批量清理工具；B5 以设置页报告入口呈现，不做逐项 UI（后续批次视需要再做）

## 子任务

### 5.1 QR 文件互通（M-13）
- `services/st/quickreply.ts`：`listQrPresets()`（读 settings 响应的 quickReplyPresets）、
  `saveQrPreset(set)`、`deleteQrPreset(name)`
- QR store（B1 本地版）升级：本地 QR 导入/导出 ST 集文件；设置页加「快捷回复（ST 文件互通）」
  卡片：列出 ST 集文件、查看/编辑 label+message、保存写回
- 会话页 QR 按钮条支持从 ST 集读取（优先级：App 本地 > ST 集，UI 可见来源标记）

### 5.2 STscript 子集（M-9）
- `services/st/stscript.ts`：解析器（`/cmd arg` 顺序拆分 + `|` 管道 + `{{pipe}}` 替换 + 引号参数）
- v1 命令集：`/echo /send /genraw /setvar /getvar /addvar /random /pick /delay /flushvar /if`
  （if 支持 `{{getvar::x}} == value` 简式；变量存 chat_metadata.variables，与 ST variables 扩展互通）
- 执行上下文：注入 chat store 句柄（/send 直接发消息，/genraw 生成并返回文本经 {{pipe}} 传递）
- 入口：QR 消息以 `/` 开头 → 脚本执行（设置页有开关）；会话输入框同样支持
- 自检：解析器 + 变量 + 管道 + 随机/挑选纯函数断言

### 5.3 Instruct 模板（M-14）
- `services/st/instruct.ts`：`applyInstruct(messages, instruct, name1, name2) -> string`
  （Text Completion 模式专用；语义对齐 formatInstructModeChat：角色序列/首末变体/名字/wrap/宏）
- `stores/chat.ts` 文本生成通路：settings.power_user.instruct.enabled 时，把 messages 拼接为
  instruct 文本作为 prompt（替代 messagesToPrompt）；stop sequence 取 instruct.stop_sequence
- 设置页只读展示当前 instruct 预设名与关键参数（编辑在 ST 网页端，模板数据互通）

### 5.4 NovelAI 源（M-15 主体）
- `services/st/api.ts`：source 'novel' 分支 —— 走 `/api/novelai/generate`，
  sampler 映射（temperature→temperature、maxTokens→max_length、topP/topK/typicalP、
  repPen/repetition_penalty_range；模型名取 settings.novel_model?App 设置加模型输入）
- 服务不可用（无密钥 400）时错误提示引导到 ST 配置密钥
- Horde（/generate-text + task-status 轮询）后置到 B6（方案明示）

### 5.5 角色重命名 + 批量操作（M-18 适配版）
- `services/st/data.ts`：`renameCharacter(avatar, newName)`（/api/characters/rename）
- 联系人右键加「重命名」；成功后刷新角色列表与会话列表
- 批量操作：联系人列表进入多选模式（长按/复选），批量打标签 / 批量删除 / 批量导出 PNG
  （本地循环调用已有单卡接口）
- data-maid：设置页加「数据巡检」按钮 → /api/data-maid/report 弹窗展示清单 → 确认后 /finalize

### 5.6 验收
- 离线自检：STscript 解析/管道/变量/if；instruct 拼接（对齐 ST 用例：wrap、{{name}}、首末序列）
- 在线冒烟（ST 起来后）：QR 集读写互通、重命名后 ST 端角色目录迁移、NAI 源生成一条

## 明确不做（范围外，记入文档）
- STscript 全量命令（/commands 面板、/gen 全参数、/popup 等）与闭包式嵌套管道
- Horde 生成源（轮询任务模型，B6）
- data-maid 逐项 UI（仅报告+一键清理）
- Instruct 模板编辑器（只读透传，编辑走 ST 网页端）
