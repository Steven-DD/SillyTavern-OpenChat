## 一、选型总表

| 层 | 选型 | 版本基线 | 理由 |
|----|------|----------|------|
| 桌面框架 | **Tauri** | 2.x | 体积小（Rust 内核）、原生 sidecar 支持、跨平台（先 Windows 后全平台）、WebView2（Windows 自带） |
| 前端框架 | **Vue 3** | 3.5+ | 老板拍板；CompositionType 响应式适合聊天流高频更新 |
| 构建工具 | **Vite** | 6.x | Vue 官方标配，HMR 快 |
| 语言 | **TypeScript** | 5.x | 大型前端必备，ST API 类型化封装 |
| 状态管理 | **Pinia** | 2.x/3.x | Vue 官方推荐，DevTools 友好 |
| 路由 | **Vue Router** | 4.x | 三栏壳内内容路由（对应一致性规则） |
| 图标 | lucide-vue-next | latest | 轻量、风格统一、MIT |
| 工具库 | nanoid / dayjs / zod | latest | ID / 时间 / API 响应校验 |
| CSS | 原生 CSS Variables + Scoped CSS | — | 主题 token 见《视觉主题设计 v0.1》；不引入重 UI 框架（聊天界面定制化高，自研组件可控性最好） |
| 测试 | Vitest + Playwright(Tauri) | — | 单元 + E2E，后配 |

## 二、整体架构

```
┌─────────────────────────────────────────────────────┐
│ Tauri App (Windows 先行)                             │
│                                                     │
│  WebView (Vue 3 SPA)          Rust Core             │
│  ├─ 三栏布局壳                 ├─ sidecar 生命周期    │
│  ├─ 聊天区/状态条/SSE渲染       │   (启动/健康检查/退出)│
│  ├─ Pinia stores              ├─ HTTP 通道 ─────────┼──→ ST 后端
│  └─ API SDK 层 (typed)        │    (绕过WebView CORS) │   127.0.0.1:PORT
│                               └─ 数据目录管理         │   (Node + ST release)
└─────────────────────────────────────────────────────┘
```

### 2.1 ST Sidecar 管理（Rust 层职责）

- **打包**：便携 Node runtime + ST release 源码目录随安装包分发
- **启动**：应用启动 → Rust 拉起 `node server.js`（固定 127.0.0.1 + 随机/固定端口）→ 轮询健康检查（GET /api/settings/get 或 /csrf-token）就绪后再加载前端数据
- **退出/崩溃**：应用退出时 kill 进程树；sidecar 意外退出 → 前端状态条转"已断开"+ 自动重启（限 3 次）
- **数据目录**：ST `data/` 重定向到 `%APPDATA%/<app>/st-data/`（升级不丢数据）

### 2.2 HTTP 通道（CORS 与 SSE 关键决策）

**问题**：WebView origin（tauri://localhost）≠ ST origin（127.0.0.1:PORT），ST 默认无 CORS 头，直连 fetch 会被 WebView 拦截。

**方案（采纳）**：使用 `@tauri-apps/plugin-http`（tauri-plugin-http）——前端调用经 Rust 层转发，不受 WebView CORS 约束。
- ⚠ **风险点**：该插件对 SSE 流式响应（ReadableStream）的支持需第一周 spike 实测
- **备选方案 B**（若 plugin-http 不支持流式）：Rust 层自写轻量转发（axum/hyper 反代 + SSE 透传，前端 EventSource 连本地转发端口）
- **备选方案 C**：ST 侧配置 CORS 中间件（社区有先例，但动 ST 源码，违背"最小改造"原则，仅作兜底）

> 无论 B/C，`sseStream.ts` 解析器与 API SDK 层接口不变，切换成本可控。

## 四、关键实现约定

1. **一致性规则的代码落点**：`AppShell.vue` 是唯一布局壳；左栏四入口写死；中栏/右栏内容由路由驱动（`<RouterView>` 分层），**禁止**任何全屏覆盖式独立页面
2. **流式不中断**：二级面板展开只改 CSS grid 列宽（transition width），聊天虚拟列表不重挂载；SSE 写入 store，组件只订阅
3. **状态条数据源**：仅 `connectionStore`（连接状态/模型名）+ `chatStore`（上下文/本轮 tokens）；设置页测试连接写 connectionStore，全应用响应式联动
4. **API 唯一出口**：所有 HTTP 走 `api/` 层，组件禁止直接 fetch——便于切换 HTTP 方案与统一错误处理
5. **类型安全**：API 响应 zod 校验后入 store，防 ST 升级字段变化静默崩 UI
