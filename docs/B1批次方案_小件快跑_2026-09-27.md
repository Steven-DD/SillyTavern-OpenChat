# B1 批次方案：小件快跑（M-1 / M-2 / M-3 / M-4）（2026-09-27）

> 对应盘点 v2.0 第四节的 M-1/M-2/M-3/M-4。原则：接口级 + UI 级小件，一次批次全部消掉。

## 子任务拆分

### 1. M-1 背景图（/api/backgrounds）
- 服务 `services/st/backgrounds.ts`：
  - `listBackgrounds()`：POST `/api/backgrounds/all` → `[{filename, isAnimated}]`
  - `backgroundUrl(name)`：`${stBase()}/backgrounds/${encodeURIComponent(name)}`（ST 静态路径，走中继）
- 状态：新 pinia `stores/background.ts`，localStorage `app.bg`（`{name: ''}`，空 = 不使用）
- 应用：选中后把 `--page-chats-image: url("…")` 写到 `document.documentElement`（base.css 已预留
  `.page[data-page=chats] { --page-bg-image: var(--page-chats-image) }`）；清除时移除
- UI：设置 → 通用 新卡片「聊天背景」：背景列表（点选应用 / "不使用"）
- 验收：ST 在线时列出服务端 backgrounds 目录；点选后聊天页背景即时变化且刷新后保持

### 2. M-2 QR 发送模式
- `QuickReply` 增加字段 `mode: 'send' | 'insert'`（默认 send），存 extension_settings.stchat_quick_replies
- 行为：send = 直接发送（现状）；insert = 把 message 追加进输入框草稿（不自动发送）
- UI：ExtensionsCard 的 QR 行加模式下拉；聊天页按钮条行为按 mode 分派
- 验收：insert 模式点击后草稿出现文本且不发送

### 3. M-3 Continue 续写（CC 通道）
- prompt.ts 新增纯函数 `withContinue(messages)`：在 messages 尾部追加 `{role:'user', content:'[Continue]'}` 指令
- chat.ts `continueReply()`：
  - 守卫：末条为 AI、非 pending/error、非流式中
  - buildPrompt（buildHistory 天然包含末条 AI 部分文本作为 assistant 轮）→ withContinue → generate
  - 增量**追加**到末条消息内容；同步写回当前 swipe（编辑同步同款逻辑）；行级落盘
  - 复用 streaming/abortCtl（可停止、可退避回退）
- UI：末条 AI 气泡工具条加「⏵ 续写」按钮
- 已知近似（注明）：ST 按源使用 assistant prefill；本版统一走 [Continue] 指令，跨源一致但重复风险略高

### 4. M-4 Impersonate 代写（简化版，CC 通道）
- prompt.ts 新增 `withImpersonate(messages, userName)`：追加指令
  `{role:'user', content:"(Write 老板's next message in first person. Output only the message text.)"}`
- chat.ts `impersonate(): Promise<string>`：buildPrompt → withImpersonate → generate（复用 streaming/abort）→ 返回文本
- UI：输入框工具条「代写」按钮 → 结果写入输入框草稿（不自动发送，与 ST 一致）
- 验收：点「代写」后输入框出现以用户口吻的消息草稿

### 5. 自检与冒烟
- 离线断言：withContinue/withImpersonate 消息构造、bg URL 拼接、QR mode 分派
- ST 在线冒烟：backgrounds/all 真实调用；continue/impersonate 真实生成各一次
