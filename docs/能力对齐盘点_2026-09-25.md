| 会话删除        | 二次确认弹窗 + jsonl 删除                                    | ✅                         |
| 新建会话配置      | 名称/开场白/人设/参数，写 chat_metadata（ST 可读）                  | ST 无此弹窗（App 增强，但元数据结构互通）  |
| 人设锁定到会话     | chat_metadata.persona，与 ST 字段一致                      | ✅ 同一机制                    |

## 三、◑ 部分对齐（9 项）

| 功能                | App 现状                                                                                              | ST 网页端                                                     | 差距                                 |
| ----------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------- |
| **3.1 世界书参与生成**   | 管理页完整，但 **buildPrompt 不注入任何世界书条目**（prompt.ts 无 worldinfo 逻辑）                                        | world-info.js 扫描关键词→激活→按 order/position 注入                 | ⚠ **当前世界书对聊天内容零影响**，管理页形同摆设。**P0** |
| **3.2 消息级操作**     | 仅「重新生成」                                                                                             | 单条消息编辑 / 删除 / 重发 / swipe 左右切换                              | 编辑与删除是高频操作，缺失体感明显                  |
| **3.3 开场白备选**     | 新建会话配置里可选备选问候（一次性选定）                                                                                | 首条消息 swipe 随时切换                                            | 场景覆盖窄（不能中途换）                       |
| **3.4 生成源**       | Chat Completion 12 源（Google/OpenAI/Claude/OpenRouter/DeepSeek/月之暗面/智谱/硅基/MiniMax/xAI/Mistral/自定义兼容） | 30+ 商业源 + Text Completion 本地推理（KoboldCpp/llama.cpp/Ollama） | 常用源够用；**本地模型全不支持**                 |
| **3.5 宏替换**       | {{char}}/{{user}}/<BOT>/<USER> 4 个                                                                  | 50+（{{time}}/{{date}}/{{random}}/{{roll}}/{{pick}}…）       | 复杂卡（依赖时间/随机宏）表现会不一致                |
| **3.6 上下文裁剪**     | maxContext + 粗估 token（CJK≈1/字，其余≈4字符/token）                                                         | 后端真 tokenizer（SentencePiece）精确计数                           | 估算偏保守，极端情况多裁历史                     |
| **3.7 会话搜索**      | 中栏本地过滤（名称/预览）                                                                                       | /api/chats/search 全文搜索消息内容                                 | 搜不到历史消息正文                          |
| **3.8 Prompt 模板** | 固定模板（描述/性格/场景/示例 + 人设注入）                                                                            | Prompt Manager：main/jailbreak/NSFW 可编辑，按源适配                | 系统提示不可定制，越狱/风格玩法缺失                 |
| **3.9 消息渲染**      | 纯文本气泡                                                                                               | Markdown + 代码块 + 引用块渲染                                     | 长回复排版、代码展示差距明显                     |

## 六、建议的补齐顺序

1. **世界书注入**（P0）——管理页已建好却对生成无效，是当前最大的一张「画饼」，补上后世界书页价值立刻兑现
2. **消息右键菜单**（P1）——编辑/删除/重发，复用刚做的 CtxMenu，成本低体感强
3. **Markdown 渲染**（P1）——接 marked，半天级工作量
4. **Swipe**（P1）——配合开场白备选，把 ST 的核心体验补齐
5. 记忆三件套、推理展示、群聊按 v1.1 排期
