## 一、项目一句话

给 SillyTavern（ST）套一层微信风格桌面壳：**App 是唯一入口，底层锁定稳定版 ST，不自建后端**。

推论（2026-09-22 已定案）：
1. ST 版本要**钉住且可回滚**，升级前必须自动备份数据（ST 升级有 `migrateUserData` 会改数据格式）
2. 唯一入口 ⇒ 映射可「App 为准」单向下行，无需双向合并
3. settings.json 仍是共享文件，写入须防冲突

## 五、架构要点（改代码前必看）

```
浏览器 (http://tauri.localhost)
   ↓ fetch（不参与 Cookie）
Rust 中继 (relay.rs) —— 代持 ST 会话 Cookie
   ↓ 127.0.0.1:8000
ST sidecar（由 App 托管，带 --dataRoot / --configPath）
   数据：<应用配置目录>/st-runtime/{data, config.yaml}
```

- **前端基地址 `st.base`**：开发留空（同源走 Vite 代理），生产由 `st_relay_base` 写入中继地址。
  ⚠ 不得缓存为模块级常量（桥接晚于模块求值）；头像/缩略图 URL 必须拼 `stBase()`
- **数据路径唯一裁决点 = `PluginHost::data_paths()`**：环境变量 `ST_CHAT_DATA_DIR` → `plugins.json` 绑定 → ST 默认
- **五条安全铁律**：① 只复制不删源（回滚 = 改字段）② ST 运行中禁止迁移（外部实例直接拒绝）③ 目标非空即拒绝 ④ 复制后逐文件校验，不过则清理新建目标且不切换绑定 ⑤ 绑定失效回退
- **装完不自动切绑定**（S4 原则）

## 七、已知限制（如实说明）

1. **并非「ST 目录完全只读」**：实测 ST 运行时持续写入的只有 `data/` 与 `config.yaml`（均已外移）；`plugins/`、`public/scripts/extensions/third-party/`、`backups/` 仍指向 ST 目录，只在主动安装时才写。macOS 只读 `.app` 下需额外处理。
2. **迁移后的外移副本不自动清理**：回滚后仍占约 29MB，当前需手工删除。
3. **迁移无断点续传**：失败会清理本次新建目标并回原状态。29MB 场景无感，GB 级建议后续补。
4. **安装包未内置 ST 与 node**：当前依赖应用内组件安装（或后续预打包 zip）。
