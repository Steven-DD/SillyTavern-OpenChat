# 会话页面改造方案 v1.0

> 范围：4.2 单条消息编辑/删除/重发 · 4.3 Markdown 渲染 · 4.4 Swipe 备选回复 · 4.6 推理内容展示 · 4.10 会话导出/分支/书签
> 日期：2026-09-25 · 基于 App 当前代码 + ST 1.19.0 源码逐项核对

---

## 一、流式 AI 对话组件调研结论

| 候选 | 结论 | 理由 |
|---|---|---|
| **streamdown-vue3** ✅ 选定 | Vue 3 原生，Vercel 官方 Streamdown 的社区移植 | 专为 LLM 流式设计：**未闭合语法自动补全**（半截代码块/加粗不闪烁）、**块级 memo**（只重渲染变更块，长对话不卡）、rehype-sanitize **默认安全**（无 v-html 裸奔）、Shiki 高亮为可选插件（按需引入） |
| markstream-vue | 备选 | 能力类似（流式 markdown + Mermaid/KaTeX），生态略新 |
| markdown-it + DOMPurify | 备选（自研路线） | 最轻，但要自己处理半截 fence、块级 memo，工作量大 |
| deep-chat（web component） | ❌ 不用 | 它是**整套聊天 UI**，会顶掉我们微信风格的气泡/右键菜单/Swipe 控件，深度定制反而要对抗它 |
| ai-interface-vue | ❌ 不用 | 未发 npm（只能 GitHub 装），样式固定，且不带消息操作菜单——我们反正要自研操作层 |

**推理内容展示**：不需要重型组件。ST 侧就是 `extra.reasoning` 纯文本字段，自研一个**可折叠面板**（流式时实时展开、结束后自动折叠成「已深度思考 · Ns」一行，点击展开并走 Markdown 渲染），与 streamdown 组合即可。

**新增依赖**：`streamdown-vue3`（+可选 `shiki`，本阶段不装 mermaid/katex）。

## 二、数据层地基（先行修复，隐藏 bug）

**发现一个现存 bug**：`toStMessages` 写回时 `extra: {}` 硬编码空对象——每次保存会话都会**抹掉 ST 侧消息上的 swipe、推理、书签链接等全部扩展字段**。做 Swipe/推理前必须先修，否则功能做完一保存就丢。

改造：

| 项 | 内容 |
|---|---|
| `DisplayMessage` 扩展 | `extra?: Record<string,unknown>`（透传原样保留）；`reasoning?`（读自 `extra.reasoning`）；`swipes?: string[]` + `swipeId?: number`（ST 格式：`mes.swipes` 数组、`mes.swipe_id` 当前下标）；`bookmarkLink?`（读自 `extra.bookmark_link`） |
| `toDisplayMessages` | 解析上述字段；`swipes` 缺省时视为 `[mes]` |
| `toStMessages` | 写回时保留原始 `extra`（无则 `{}`），`swipes/swipe_id` 原样回写——与 ST 文件双向无损 |
| `api.ts` 生成链路 | SSE 增量解析增加 `reasoning_content` / `reasoning` 字段捕获，流式期间写入当前消息的 `reasoning` |

保存策略不变：任何修改后 `saveCurrent` 全量重写 jsonl（ST 兼容）。

## 三、各功能设计

### 4.3 Markdown 渲染
- 气泡内替换 `<span class="txt">` → `<Streamdown :content>`；用户消息保持纯文本（微信风格，AI 消息才渲染）
- 主题 token 适配：代码块/表格配色走 CSS 变量，明暗主题自适应
- 流式期间 streamdown 自动补全未闭合语法；光标 `▍` 保留在气泡尾部

### 4.6 推理内容展示
- 助手气泡上方插入折叠块：流式中自动展开实时显示；`pending` 结束后自动折叠为「💭 已深度思考 · Ns」
- 展开态内容走 streamdown 渲染；数据存 `extra.reasoning`（与 ST 完全互通，ST 网页端可见可编辑）

### 4.2 单条消息编辑/删除/重发
- 复用现有 `CtxMenu` + `ConfirmDialog`：**右键消息** → 菜单：复制 / 编辑 / 重新生成（仅末条 AI） / 从此重发（用户消息） / 添加书签 / 删除
- **编辑**：气泡原位变 textarea，Enter 确认 / Esc 取消，保存后落盘
- **重发**：截断该用户消息之后的所有消息 → 直接 `generateReply`（对齐 ST「从这里重新生成」）
- **删除**：走 ConfirmDialog 弹窗（危险操作规范）

### 4.4 Swipe 备选回复
- 末条 AI 消息气泡下方显示 `‹ 2/3 ›` 控件（仅末条、非流式时）
- `regenerate` 增强：该消息已有 swipes 时**追加**新备选（swipe_id 指向新条），不再丢弃旧回复
- 左右切换 = 改 `swipe_id` + 气泡内容切换 + 落盘；生成中禁用
- 数据格式与 ST 完全同构，ST 网页端打开同一会话可继续 swipe

### 4.10 会话导出 / 分支 / 书签
- **导出**：会话菜单「导出会话」→ Tauri 保存对话框 → 写出原版 .jsonl（`/api/chats/export` 拉流，ST 互通）；另加「复制为文本」
- **分支**：右键任意消息「从此分支」→ 复制前缀消息为新会话文件（命名 `原名-branch-时间戳`，ST 风格）→ 自动打开新会话；原会话不动
- **书签（checkpoint，ST 同构）**：右键消息「添加书签」→ 复制当前会话为独立文件 + 源消息 `extra.bookmark_link` 记链接 → 气泡旁显示旗帜图标，点击跳转该书签会话

## 五、风险与说明

- **旧会话兼容**：存量 jsonl 无 swipes 字段 → 读时视为 `[mes]`，首次 swipe 操作时补全，ST 同款行为
- **全量重写保存**：消息编辑/删除后仍是整文件重写；对超长会话（万条级）有性能上限，当前体量无碍，后续可换 `/api/chats/save` 的增量方案
- **重发 = 截断再生**：与 ST 语义一致（ST 也是丢弃后续消息重新生成），不可恢复的截断在右键菜单文案里明确提示
