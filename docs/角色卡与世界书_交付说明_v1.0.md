> 2026-09-25 凌晨 · 老板睡前布置的长任务 · 目标：导入《林晚棠_全剧本修罗场终极版.json》
> 状态：**全部完成，端到端验证通过** ✅

## 一、交付功能

### 1. 角色卡：新建 + 导入（与 ST 侧一致）

入口：角色卡中栏「＋ 新建角色卡」→ 展开 mini 面板：

| 动作 | 说明 |
|---|---|
| 新建空白卡 | 输入角色名 → `POST /api/characters/create`（multipart，默认头像） |
| 导入文件… | 支持 ST 角色卡 **JSON / PNG / charx**（yaml/byaf 也放行了）→ `POST /api/characters/import` |

**内嵌世界书自动处理**：导入的卡若内嵌 `character_book`（v2 spec，林晚棠卡即此类），
App 自动完成 ST「导入内嵌世界书」的两步（复刻 world-info.js:5731，免确认弹窗）：
1. `convertCharacterBook`（TS 复刻 ST world-info.js:5617，字段默认值一一对应）
   把 spec 格式转成 ST 世界书格式 → `POST /api/worldinfo/edit`
2. `POST /api/characters/edit` 传 `world` 字段 → 写入 `data.extensions.world` 绑定

### 2. 世界书：新入口（左栏角色卡下面）

- 左栏新增「世界书」入口（Lucide book-open 图标），路由 `/worlds`
- **中栏**：搜索 + 「＋ 新建世界书」面板（新建空白书 / 导入 JSON）+ 世界书列表
- **右栏**：世界书详情——简介、条目列表（标题/关键词(主+次)/内容/常驻/位置/停用 徽章）、删除（两步确认）
- API：`/api/worldinfo/list | get | edit | import | delete`
  （⚠ ST **没有 create 端点**，新建 = `edit` 一个空 `entries`，与 ST 前端行为一致）

## 二、调查结论（ST 1.19.0 源码实测）

| 机制 | 结论 |
|---|---|
| 上传字段名 | 全局 `multer.single('avatar')`（server-main.js:269）→ **所有上传字段都叫 `avatar`** |
| 角色卡导入 | `/import` 保留 v2 JSON 的 `data.character_book` 原样入卡；**v2 卡会被内部升为 v3 存储**（实测 spec=chara_card_v3 3.0） |
| 内嵌书导入 | **纯前端逻辑**（后端不管）：convertCharacterBook → worldinfo/edit → characters/edit 传 world |
| `file_name` 坑 | `/import` 返回的 `file_name` 可能不带 `.png`，`/get` 需要带 → App 已归一化 |
| `/create` 返回 | **纯文本** avatarName 非 JSON（App 已按 text 解析） |
| 编辑保绑定 | `/characters/edit` 是全量重写，**不传 `world` 会把绑定抹成空**（实测确认，App 的 saveCard 已修） |
| 世界书新建 | 无 create 端点，edit 空 entries 即新建 |
