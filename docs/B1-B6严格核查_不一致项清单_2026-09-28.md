> 核查方法：B1-B6 六份批次方案的"已知裁剪"全部重审 + 以代码为准逐项对照 ST 1.19.0 源码

## P0 缺陷（3 项，建议立即修）

### P0-1 群聊内消息操作全部不落盘（B4）
- **现象**：群聊会话（`group` 非空、`currentAvatar/currentFile` 为空）时，以下操作只改内存，刷新即丢：
  `/sys` 旁白（`addNarrator`）、`toggleHideMessage`、`editMessage`、`removeMessage`。
- **根因**：这些函数的行级落盘分支要求 `currentAvatar && currentFile`（chat.ts:2009/2032/1964/1984），
  群聊下跳过 `chatMutateLines` 后回落 `saveCurrent()`，而 `saveCurrent` 第一行早退（chat.ts:2062）；
  群聊专属通路 `saveGroupLines`（chat.ts:1496-1508）在这些函数中完全未被调用。
  `/sys` 的脚本入口（chat.ts:1413）也没有群聊拦截——UI 虽隐藏了气泡按钮，但斜杠命令可触发。
- **对照**：ST 网页端群聊消息操作走 `/api/chats/group/save`，全部落盘。
- **修复方向**：这些函数增加群聊分支（改 `groupLines` + `saveGroupLines()`）；或 UI + 脚本入口统一拦截。

### P0-2 世界书 cooldown 永不生效（B3）
- **现象**：App 在条目激活时**同时**置 sticky 与 cooldown 计数并每轮同步递减
  （worldinfo.ts:281-288、308-315）→ sticky 消耗完时 cooldown 也已归零，cooldown 分支形同虚设。
- **对照**：ST 是 sticky 结束那一刻才立起 cooldown（world-info.js:518-528，end = 当前消息数 + cooldown）。
- **修复方向**：cooldown 计数改为 sticky 归零时才设置。

### P0-3 群聊激活策略语义错位（B4）
- **现象**：App 把 activation_strategy=2 实现为 talkativeness 掷骰（group-orchestrate.ts:55-80, 90-91）。
- **对照**：ST 1.19.0 的策略枚举是 `{NATURAL:0, LIST:1, MANUAL:2, POOLED:3}`（group-chats.js:122-127）——
  **策略 2 是 Manual（非用户输入时 shuffle 挑 1 人，group-chats.js:1029-1031）**；
  talkativeness 掷骰属于 **NATURAL(0)**（activateNaturalOrder，group-chats.js:1271-1305）。
- **连带**：1.19.0 中 generation_mode（SWAP/APPEND）只影响**卡片合并**（group-chats.js:439-441, 501），
  发言人数完全由 activation_strategy 决定；App 的 pickSpeakers 仍是旧语义（SWAP=轮换单人 /
  APPEND=全体发言）。**App 的群聊激活模型与 1.19.0 网页端实质不同**（对旧版 ST 导出的群尚可，
  与 1.19.0 互通的激活顺序会不一致）。
- **修复方向**：pickSpeakers 重写为 1.19.0 语义：0=NATURAL 掷骰、1=LIST 顺序、2=MANUAL 随机 1 人、
  3=POOLED；generation_mode 移交"成员卡合并"职责（每成员 prompt 用各自卡 = SWAP 行为已隐式满足）。

## P1 偏差（7 项，与网页端行为不同、用户可感）

### P1-1 Continue 用 [Continue] 指令而非 prefill 续写（B1）
- App：`withContinue` 追加 `{role:'user', content:'[Continue]'}`（prompt.ts:550-552）。
- ST：把末条消息移入 prompt 尾部、截掉输出后缀，**让模型从半截内容无缝续写**（script.js:4866-4867、
  4794-4809；CC 通道另有 continue_postfix 空格处理 4977-4980）。
- **影响**：模型可能输出元话（"好的，继续："）、先复述再续；Text+Instruct 下还会产生换轮断点
  （instruct.ts:125-128 尾部补 output_sequence 前缀 + [Continue] 轮）。
- B1 文档标注为"已知近似"，严格核查确认差异真实存在且影响输出质量。修复 = prefill 化（工作量中等）。

### P1-2 Instruct 首末序列判定条件错位（B5）
- App：first/last 按"**该角色的第一条/最后一条**"判定（instruct.ts:64-68, 80-98）——
  first_input_sequence 会错误打到第一条用户消息；last_output_sequence 会错误打到末条 AI 回复。
- ST：`first_*` **只作用于历史第 0 条（开场白）**（script.js:4784-4787）；`last_input_sequence` 作用于
  最后一条用户消息（4789-4792）；`last_output_sequence` **仅在 continue 时**使用（4794-4809）；
  `last_system_sequence` 用于 quiet prompt（instruct-mode.js:603-607），App 未实现 prefix 逻辑。
- **影响**：使用含首末变体模板（如 mistral 系）的用户，拼接结果与网页端不同。
- B5 自检断言是按 App 自身语义写的，没有覆盖到这个错位。

### P1-3 世界书 timedEffects 计数与 ST 不互通（B3）
- App 写 `chat_metadata.timedEffects = {uid:{sticky,cooldown}}`（chatdoc.ts:310-341）；
  ST 用 `chat_metadata.timedWorldInfo = {sticky:{key:{hash,start,end}}, cooldown:{...}}`
  （world-info.js:479-506）。**两边互不读取**——同一会话在网页端与 App 轮流使用时计数各自独立。
- 另：B5 世界书编辑器 UI 提示"App 注入侧暂未生效"（WorldsMain.vue:469）**与代码不符**
  （注入侧 B3 已实现，worldinfo.ts:272-290），提示文案需要更正。
- 修复方向：读写改用 ST 的 timedWorldInfo 结构（hash/start/end 语义），并删错误提示。

### P1-4 Horde 请求体缺关键字段（B6）
- `max_context_length` 写死 2048（api.ts:159），不随设置、不按 worker 能力收缩
  （ST 有 auto_adjust_context_length，horde.js:147-184）；
- **缺 `models` 字段**（服务端原样透传，缺失时 aihorde 分配不可控或拒绝；horde.js:213-219）、
  缺 `trusted_workers`；
- prompt 用 messagesToPrompt 简拼，**Instruct 序列/stop 全部丢失**（ST 的 horde 是 Text Completion，
  走 instruct 拼接）。

### P1-5 NAI 采样参数缺口大（B5）
- App 只传 9 个参数（api.ts:234-248）；ST 全集含 sampler **order**（采样器顺序）、typical_p、top_a、
  tail_free_sampling、phrase_rep_pen、slope/whitelist、mirostat、math1_*、**stop_sequences**
  （Instruct stop 序列在 NAI 通道丢失）、**bad_words_ids**（`{{banned}}` 宏禁词未接入）、
  logit_bias_exp（novelai.js:210-246）；且无 clio/kayra/erato 模型差异（默认 bad words / eos / 基址）。
- 另：App 非流式（ST 流式）——批次方案已注明，属有意取舍。

### P1-6 QR 导出文件缺字段 + 数据源误解（B5）
- 导出 body `{id, name, qrList:[{label,message,enabled}]}`：ST 端 /save 只校验 name、原样落盘
  （quick-replies.js:10-18）→ 能保存，但文件缺条目 `id`（网页端新增条目时 idIndex 计算会 NaN 化，
  QuickReplySet.js:211-212）、`enabled` **不是网页端字段**（网页端显隐用 isHidden，App 的禁用在
  网页端失效）、缺 version:2/idIndex/set 级配置。
- 更重要的认知修正：网页端运行数据源是 **settings.json 的 quickReplyPresets**，
  QuickReplies/*.json 只是扩展的手动双写备份（QuickReplySet.js:376-389）——
  App 导出的文件**不会被网页端自动加载**，B5 文档"网页端直接可用"表述过强。

### P1-7 Impersonate 为简化指令版（B1，已知，严格复查维持）
- ST：impersonation prompt + 无角色 system 轮 + 历史尾部不添加 assistant 前缀；
- App：`withImpersonate` 指令近似（B1 已注明），输出首行可能带模型自称。维持 P1 记录。

## 已核对且一致的项（抽样记录）

- 群聊成员 prompt 的"标名 assistant + 指令块"方向正确（与 ST 的 name 机制等效近似）；
- QR 导入方向（ST 集 → App）字段映射无缺失；
- classify 返回形状兼容两种历史格式、go_emotions 标签集同源；
- sprites path 中文角色名的 URL 处理与网页端等价；
- 世界书 inclusion group / ignoreBudget / 递归 / selective logic 语义与 ST 一致（B5/B3 自检覆盖）；
- Instruct 的 wrap 连接、{{name}} 宏、stop 只含 sequences 等主语义正确（仅首末判定错位）。

## 修复优先级建议

1. **P0-1**（群聊落盘缺陷，用户数据丢失级）→ 半天
2. **P0-3**（群聊激活语义，互通正确性）→ 半天
3. **P0-2 + P1-3**（timedEffects 一起改：cooldown 时序 + timedWorldInfo 互通）→ 半天
4. **P1-4**（Horde 加 models/trusted_workers + 动态上下文 + instruct 拼接）→ 2 小时
5. **P1-2**（Instruct 首末判定）→ 2 小时
6. **P1-6**（QR 导出补字段/isHidden）→ 1 小时
7. **P1-1 / P1-5**（Continue prefill 化 / NAI 参数全集）→ 各半天~1 天
