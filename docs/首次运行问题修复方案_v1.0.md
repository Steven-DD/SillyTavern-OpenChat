## 问题 1 · 角色卡头像没显示

**是否属实**：属实（表现层面），根因有两种可能，需现场确认。

**现状代码**：
- `views/ContactsMid.vue:62` —— `<img class="ava" :src="avatarThumb(c.avatar)" :alt="c.name" />`，**没有 `@error` 兜底**
- 同类裸 `<img>` 共 5 处：`ChatsMain.vue:89/126`、`ChatsMid.vue:54`、`ContactsMain.vue:96`、`ContactsMid.vue:62`
- `services/st/data.ts:205-216` —— `avatarThumb()` 对空 `avatar` 无判断，会拼出 `?file=` 空值 URL
- `avatarOriginal()` 已定义但**从未被调用**

**可能的根因（二选一，决定改法侧重）**：
1. `c.avatar` 为空 → URL 参数为空 → 请求失败 → `<img>` 静默空白
2. ST 未就绪 / 中继不通 → `/thumbnail` 请求失败 → 同样静默空白（角色列表能出来说明 ST 通，这条可能性较低）

**改法**：

| # | 动作 | 文件 |
|---|---|---|
| 1 | `avatarThumb()` 空值返回 `''` | `services/st/data.ts` |
| 2 | 抽 `Avatar.vue` 统一组件：加载失败 → 角色名首字母色块占位（推荐，5 处复用） | 新增 `components/Avatar.vue`，替换 5 处 |
| 3 | 不抽组件的话，5 处裸 img 各加 `@error` 兜底 | 上述 5 个文件 |
| 4 | 头像批量失败时给一条可见提示（现在只有列表级 `chars.error`） | `views/ContactsMid.vue`、`ChatsMid.vue` |

**风险**：低。第 2 项改动面稍大但收益最高（5 处统一）。

## 问题 2 · 安装进度条没看见

**是否属实**：属实。

**现状代码**：
- `stores/plugins.ts:133` —— `finally` 里**立即**把 `installProgress` 置 `null` → 100% 一闪而过
- `services/tauri/plugins.ts:354` —— `listen('component-install')` 在 `installComponent()` 内部注册，**可能晚于 Rust 首帧 emit**
- `installer.rs:467` —— 已安装版本**直接 emit done 后返回**，全程只发 1 次事件
- 进度本身是全局的（store），切菜单不丢 —— 这部分没问题

**改法**：

| # | 动作 | 文件 |
|---|---|---|
| 1 | 完成后延迟 1.5s 再清 `installProgress`（留住 100% 终态） | `stores/plugins.ts:133` |
| 2 | 进度条设最小展示时长（~800ms），避免短任务闪一下就没 | `views/PluginsMain.vue` |
| 3 | 监听提前注册：store 初始化时挂 `onComponentInstall`，或等 `listen` 完成再调安装命令 | `services/tauri/plugins.ts:354` |
| 4 | 早退场景（已安装 / 无需下载）补发初始 `download 0%` 事件 | `src-tauri/src/lib.rs:376-386` |
| 5 | 监听注册包 try/catch，失败时复位 `installWatcherReady` | `stores/plugins.ts:109` |

**风险**：低。

## 问题 3 · STChatData 观感不好，默认位置想放软件同目录 plugins

**是否属实**：属实，但**主要是文案误导** —— 代码默认行为已经是老板想要的样子。

**现状代码**：
- `installer.rs:54-67` —— 组件安装根目录默认**就是** exe 同目录 `plugins`（注释写明"老板定的"），只在目录不可写时才回落 `%LOCALAPPDATA%`
- 全仓**根本没有 `STChatData` 这个目录名**；它只是设置页输入框的 placeholder 示例
- `views/SettingsMain.vue:405` —— 提示文案仍写着"默认 %LOCALAPPDATA%，想省 C 盘可填 `D:\STChatData`" —— **与实际行为不符**
- 数据目录（另一回事）：`st_data.rs:36,66` → `%APPDATA%\<app-id>\st-runtime\data`

**改法**：

| # | 动作 | 文件 |
|---|---|---|
| 1 | 提示文案改为"默认：软件同目录下的 plugins；程序目录不可写时自动回落 %LOCALAPPDATA%" | `views/SettingsMain.vue:405` |
| 2 | placeholder 改为"留空 = 软件同目录/plugins"（去掉 D:\STChatData 示例） | `views/SettingsMain.vue:407` |
| 3 | 若老板指的是**数据目录**也要挪到软件同目录 → 改 `st_data.rs::external_root()` + `plugin/mod.rs:301` | 需确认 |

**风险（第 3 项）**：数据放软件同目录 = **卸载软件时数据跟着没**。建议区分对待：
- 组件 / 运行时（几百 MB，可重新下载）→ 跟软件走，合理
- 用户数据（角色卡 / 会话 / 密钥）→ 不该随卸载消失
