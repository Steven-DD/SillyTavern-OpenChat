## 四、ST 相关的致命约束（改代码前必看）

1. **绝不传 `use_sysprompt`**（保持 falsy）—— 否则 Google 侧 `contents[0].role` 变 `model`，触发 prefill 校验必然报错。
2. **messages 不能带 `name` 字段** —— `convertGooglePrompt` 会把 name 拼进正文。
3. **settings.json 写入三条铁律**：① 整体覆盖，必须「读全量 → 合并 → 写全量」② body 必须是 settings 本身，不能包 `{settings:...}` ③ 每次 save 触发 `triggerAutoSave()` 产生备份 → 映射同步必须**先比对、一致就不写**。
4. **免费层配额**：`gemini-3.8-flash` 每日 20 次；`gemini-flash-latest` 别名共享同一配额。报 `/exceeded your current quota/` 立即停止重试。
5. ST 出站代理不读 `HTTP_PROXY`，必须配 `config.yaml` 的 `requestProxy`。
6. `/api/characters/chats` 在角色尚无 chats 目录时返回 `{error:true}` —— 是「没有会话」，要归一化为 `[]`。

## 五、本机环境硬约束（踩过的坑，别再踩）

| 坑 | 结论 |
|---|---|
| bash shim 路径转换 | 传给 Windows exe 的**参数**里含盘符会被 `\`→`/`（单引号、`MSYS_NO_PATHCONV=1`、node spawn 全拦不住）。含路径的参数走 JS 内部构造或 env 传递；脚本路径本身用 `C:/` 形式 |
| 删除慢 | 曾被配置成「进回收站」→ 删 3 万文件小时级。老板切回 unlink 后 3 秒。**删除慢 ≠ 磁盘慢，先问配置** |
| bash → AppData 慢 1000 倍 | `bash` 启动的进程在非 `%TEMP%` 的 AppData 下文件操作被拖慢（1481 vs 1.7 文件/秒）。**是 bash 假象，真实用户双击不受影响**。大批量小文件操作用 PowerShell 或让用户双击 |
| 沙箱 | Bash 沙箱**禁止写盘**（`curl -o`、`echo >` 静默失败）→ 用 Write 工具或 node 内存处理；cargo 编译必须 `dangerouslyDisableSandbox: true` |
| npm | 必须带 `--registry=https://registry.npmmirror.com`（667 包 13 秒）；npm 子进程必须显式设置/清空 `HTTP_PROXY`（常驻沙箱代理 57962 不通外网） |
| Vite | dev server 必须显式 `server.host: '127.0.0.1'`（否则 Node 17+ 解析出 ::1，只绑 IPv6） |
| safe-delete | 单次递归删除 >50 条目被拦 → Vite `emptyOutDir: false` + 逐文件删 |
| rustc ICE | `error: the compiler unexpectedly panicked` → 删 `target/debug/incremental`（几万小文件，慢是正常的） |
| 代理 | 用户真实代理 `http://127.0.0.1:7890`；环境变量里的 57962 是沙箱代理，不是用户的 |
| 用户级 | 称呼「老板」，中文简洁直接；变更给前后对比表；数据必须真实查询，无数据标 `[数据暂不可用]`；验证做整体验证 |
