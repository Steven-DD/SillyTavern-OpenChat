# S2 · SillyTavern 数据区外移 — 交付说明 v1.0

> 2026-09-22 · 已在真机完成迁移与回滚的全流程验证

---

## 一、这一片解决了什么

ST 默认把用户数据写在 `<ST目录>/data`。带来两个后果：

1. **升级 / 替换 ST 会连数据一起被覆盖** → 丢角色卡、会话、API 密钥
2. **macOS 的 `.app` 包体只读** → ST 根本起不来（跨平台的前置障碍）

本片通过 ST 原生的 `--dataRoot` / `--configPath` 参数，把「可写数据」从「代码目录」里拆出来：

```
代码（只读，可随版本替换）     <ST目录>/  (server.js, node_modules, public, default)
数据（可写，永久保留）        <应用配置目录>/st-runtime/data/        ← 角色卡/会话/密钥/世界书
配置（可写）                  <应用配置目录>/st-runtime/config.yaml
```

## 三、五条安全设计（这是本片的核心价值）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **只复制，绝不删除源目录** | 回滚 = 改一个字段，**零数据风险** |
| 2 | **ST 运行中禁止迁移** | 运行中迁移会丢掉「正在写入」的数据。应用托管的实例会自动暂停并等端口真正释放；**外部实例直接拒绝**（不越权杀用户自己起的进程） |
| 3 | **目标非空即拒绝** | 不做「合并」式迁移，避免覆盖用户已有数据 |
| 4 | **复制后逐文件校验**（存在性 + 字节数） | 不通过则清理本次新建的目标目录，且**不切换绑定** —— 绝不留下「半个副本 + 已切换」的状态 |
| 5 | **绑定失效必须回退** | 若绑定的目录不存在，回退到 ST 默认位置并告警。**否则 ST 会以空数据启动，用户会以为数据丢了** —— 这是最危险的失败模式 |

## 五、怎么用

应用内：**设置 → 数据与连接 → 数据目录**

1. 看到当前位置、形态（ST 目录内 / 已外移）、文件数与体积
2. 展开「关键数据清单」——**迁移前先看清到底会搬什么**（角色卡、会话、密钥、世界书…逐项列出）
3. 点「迁移到应用数据目录」→ 出现迁移预览（源、目标、规模、阻断项、警告）
4. 「确认迁移」→ 自动暂停 ST → 复制 → 校验 → 校验通过才切换绑定
5. **重启应用生效**

命令行（排障 / 无 GUI 环境，走的是同一套宿主逻辑）：

```bat
st-chat.exe --data-plan      <配置目录>   :: 只读预览，落盘 data-plan.json
st-chat.exe --migrate-data   <配置目录>   :: 执行迁移，落盘 data-migrate.json
st-chat.exe --data-rollback  <配置目录>   :: 回滚，落盘 data-rollback.json
```

Windows 配置目录通常是 `%APPDATA%\com.datago.st-chat`。

环境变量 `ST_CHAT_DATA_DIR` 可临时覆盖数据位置（优先级最高，排障用）。

## 六、已知限制（如实说明）

1. **并非「ST 目录完全只读」**。实测 ST 运行时持续写入的只有 `data/` 与 `config.yaml` 两处（均已外移），但以下位置仍指向 ST 目录，**只在你主动安装时才写**：
   - `<ST目录>/plugins/`（服务器插件）
   - `<ST目录>/public/scripts/extensions/third-party/`（ST 扩展）
   - `<ST目录>/backups/`（仅历史迁移时写；当前只有占位 `!README.md`）

   UI 里也照实展示了这份清单。要在 macOS 的只读 `.app` 里跑，这几项还需额外处理（属跨平台切片）。

2. **迁移后的外移副本不会自动清理**。回滚后副本仍占约 29 MB，当前需手工删除。UI 文案已明确「回滚只改指向，数据不动」，但未提供「删除副本」按钮。

3. **迁移无断点续传**。失败会清理本次新建的目标目录并回到原状态（源数据不受影响），但需要整体重来。29 MB 场景无感；GB 级数据目录建议后续补。

4. **`--dataRoot` / `--configPath` 仅 standalone 模式有效**（ST 官方限制）。我们用的正是 standalone，不受影响。

## 七、顺带修掉的环境坑

- **`app_config_dir()` 返回混合分隔符路径**（`C:\...\Roaming/com.datago.st-chat`），拼出来的路径正反斜杠混杂。统一用 `st_data::display_path()` 规范化 —— 与之前 `..` 片段、`\\?\` 前缀属同一类「路径显示卫生」问题。
- **ST 的 `initConfig` 只在 global 模式创建 configPath 的父目录**（`command-line.js:283`）。非 global 下必须由我们先 `create_dir_all` 父目录，否则首次以外移配置启动会因写不了 `config.yaml` 而失败。
- **Bash 里调用 `powershell` 被安全策略拦截**（"Invoking PowerShell from Bash bypasses PowerShell security checks"）→ 查进程命令行等必须直接用 PowerShell 工具。
